# An insertion or a drop

Every PR that will sit above a change goes back to draft first (`gh pr ready --undo`, `glab mr update --draft`, then `$CHANTIER stack --draft <cr>…`), before any other step.
- Insert (`insert: <new cr> below <cr>`): order the stack with the new CR at the place named (the release stays last); rebase the new PR and each above it on the one under, push each branch (`help refused-push`), `ship` bottom up (`--conflict` by `help conflicts`), fix the body lines `ship` names; judge again what a move touched (a clean restack carries); `forge-stack rebuild`; the release PR is stale: leave it a draft and hand back, the Foreman sends it back with `redo:`; read the five checks, run the local gate at the mergeable top if its head has no pass, then after the chain check turn the PRs above ready (`stack --out-of-draft`), the release last.
- Drop (`drop: <cr> to <destination>`: `6-trash`, `3-ready` or `2-backlog/P<n>`; none means the trash): take the dropped commits out of each CR above that has no live Driver, bottom up, in its worktree: the first above, `git -C <worktree> rebase --onto <the branch now under it, or origin/<default branch>> <the dropped CR's branch>`; each next, `rebase --onto <branch under it> <that branch's head before this take>` (the `head` `stack` printed before the first rebase). A `working` CR is skipped: its Driver does it. A conflict that only needs resolving: `conflict-resolver`; code: `help stack-hold`.
- Push each moved branch, `ship` bottom up, judge what each move touched again (a drop carries when the CR's own commits are unchanged), heavy CI at the top (`help stack-hold`), then `forge-stack rebuild`: it names the dropped PR apart. A trashed CR: close its PR (`gh pr close <n>`, `glab mr close <n>`), no `--delete-branch`, no comment. A CR moved to the backlog or `3-ready`: its PR to a draft, no close, no comment, no rebase, no retarget by hand. Branch and worktree stay.
- Then the local gate at the mergeable top, the chain check, the mergeable part ready (`stack --out-of-draft`); a release above stays a draft for `redo:`. A dropped CR with an open PR and nothing on its branch needs only the last two steps; with no PR, nothing.
- `rebase: <cr> dropped` (series or parallel): rebase onto the default branch, or the `worktree:` line's branch, without the dropped CR's commits.
