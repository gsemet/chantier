# Starting a worker

- `$CHANTIER handoff <cr>` (counts nothing) and `log <cr>` say where the CR stands; your prompt's `Note:` says why it is with you. A round only for what the notes ask.
- `$CHANTIER round <cr> --note "<one-line brief>" --lease <n>` before each Coder only. Refused past the limit (exit 5): `blocked rounds: <what is still wrong>`; budget spent (exit 5, a budget message): `blocked budget: …`; refused, exit 2, nothing happened since the last round: read `handoff`, start that round's coder, or `note` why a new round is needed.
- Start each worker with the agent and model as the `team:` lines print them, passed as printed (no model printed: none passed; `agent=(generic)`: the host's generic agent). Its prompt is the output of `$CHANTIER brief <role> <cr> --batch <batch>` (the `workers:` line of `take`, `round` or `handoff`), passed unchanged, a follow-up start included, then your `Note: …` and, when the role has skills or tools, `Needs: …`. A `Needs:` you cannot meet is a `note`; do your part without it.
- Worktree: first step, `git -C <main checkout> fetch <remote> <default branch>`, then `git -C <main checkout> worktree add -b <branch> <path> <base>` (with a planning surface, from the clone `take` names); an earlier Driver's worktree is used as it is (`worktree add <path> <branch>`). Workers create none but the Verifier's detached one. Never `git branch -a`, or `git status` outside your worktree.
- More: `help cr-prompt` (the prompt lines, `phase`, notes, the reply formats).
