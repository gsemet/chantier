# Stopping a long gate

Stop only your own CR's running long gate, with `$CHANTIER gate <cr> --stop`, never another CR's (`cancel` is the steering session's, never a Driver's), and only when its result can no longer count: the head is about to move (a `rebase:` note, a change that needs a round), a red CI job that is the CR's, or the steering session's `stop`. Never because it is slow: a run that would still be a valid pass is worth more finished than restarted.
- A stopped run is recorded `stopped`: not a failure, so not a round; no pass, and it voids an earlier pass at that head: run the long gate again at the head you push.
- A gate of yours still waiting for the lock (its log says `waiting for the long gate of …`) has started no suite, and `--stop` refuses it because the lock names another CR: end the `gate` command you started, by its id. A refusal for the hour names the gate that holds the lock: report it to the steering session as it is; never read it as a stale lock.
- `long_gate.parallel` (`chantier.yaml`; 1 if absent) gates run at once; the queue: the next merge first (stack or series: the order's first CR not merged or cancelled, fix and release CRs excepted; parallel: none), then those the Foreman moved first (`gate --first`), then arrival order.
- A long gate still running at your hand-back is left to finish: the CLI records its result for the next Driver. Stop only what waits on it. When its end wakes you after your hand-back, send nothing and end your turn.
