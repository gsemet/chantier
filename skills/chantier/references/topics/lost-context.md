# A Driver out of context

A hand-back `blocked context: …` (the context reached the threshold, or the host asked the hand-back early; the text says which): restart a fresh Driver before any queued CR (a blocked CR holds no slot, so it takes the next free one): `agents set <cr> - --epoch <n>`, `take <cr> --note "resume: context" --epoch <n>`, a new Driver, `agents set <cr> <id> --epoch <n>`. No round, no ask.
- A second `context:` on the same CR with no new head, round or note since the first: `question <cr> driver out of context twice`. Only real context ends count (not `host asked the hand-back`, not `closing:`). In a report or the retro, `context: host asked the hand-back …` is "a turn ended early", with what the Driver waited for, never "out of context".
- A text starting `context: closing:` (its pushed-head `VERIFIED` at 115,000 tokens or more, or the context rule during the closing): the same path with `resume: closing`, no round, no ask, before any queued CR. A report or retro calls it "the closing step". A second one with no new step note since the first (`closing: body posted at …`, `closing: description pass VERIFIED at …`, `closing: PR ready`, `closing: PR kept draft on …`) is the same question `driver out of context twice`.
