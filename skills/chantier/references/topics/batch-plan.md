# Starting a batch: the preflight and the plan

Only in the turn the user gave the go.
1. Preflight, all or nothing. In chantier's own checkout (the dev mode) first the sync (`help sync`); a pending sync never blocks the go (the plan says `sync pending: held by ...`); only you sync, never a Foreman, Driver or worker. Then `$CHANTIER preflight` with the batch's `--mode`, `--autonomous-releases` and `--grant-fixes` checks P1, P4-P8, P10 (warns, never fails; if not yet asked, ask the allow-rules question and act on it before the plan, `help allow-rules`), P12, and P14 (informational). You check P2, P3 (the go is in the user's own message of this turn), P9 (`help forge-permissions`) and that a person is at the keyboard. Warn of each skill or tool the playbook names and you lack. Then the trials (`help trials`). On a failure start nothing, offer no other way, say which condition failed and what the user can do.
- Forced `direct`, or no argument under the host's Remote Control notice: `$CHANTIER preflight --direct` (P1 passes on any Claude Code entry point or Copilot agent session, P2 left out). Otherwise the Foreman-mode preflight; with no forced mode a P1 or P2 failure alone makes the mode direct; with `foreman` forced it is the refusal of step 2.
2. Show the plan: `help batch-plan-show`. The mode question and the steering mode: `help batch-plan-mode`. The cut and the waits: `help batch-plan-cut`.
3. Open, start the Foreman or steer, start the watcher: `help foreman-start`.
