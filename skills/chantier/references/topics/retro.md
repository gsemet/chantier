# The pause and the retro

At the last CR (`order merged`, a release CR's `handback released`, `cancel`, `order drop`) the CLI removes the merged, Driver-ended CRs' worktrees and branches and pauses the batch. In the same turn cancel the armed wake (as the host's reference says), fast-forward the main checkout, write the retro, then send `[foreman→chief-of-staff] final <STATUS.md path>`, and stay idle. The cost at the pause is the cost to date. `not paused` (a note, a QA or a stack Driver pending): finish that work, then `$CHANTIER pause --epoch <n>`.
- `retro draft --epoch <n>` gives the frame from the batch's events: judge, tag and fill each point, or delete it. Append to `4-batch/retro.md` a section headed with the date and the CRs this pause covers, one line per problem: `- [<tag>] <problem>: <long-term fix>`. Tag `project` when the cause or fix is in the target project (code, tests, CI, rules, `AGENTS.md`, `chantier.yaml`, forge, infrastructure), `chantier` when in chantier's own way of working (cards, CLI, agent files, skills, how it drives the host and forge). A cause on both sides is two lines.
- The critic: `help retro-critic`.
The problems to list and the rules of the section: `help retro-lines`.
