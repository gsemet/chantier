# The restack pass

- Run `$CHANTIER stack` before a take's first rebase: its `head` values are the old heads. The stack is what `take stack` gave, each row labelled with the CR's hand-back state and its PR's draft flag; a CR is handed back ready when its label starts with `ready`; the mergeable part is the run from the bottom of `ready, PR out of draft (…)` rows. Never run `take stack` yourself.
- Ordering: name with `$CHANTIER stack <cr>…` every CR with a PR, bottom first: the handed-back-ready first (those already in place, then the newly ready), then the working and blocked (those already stacked, then the newly joined). Not named: CRs to come, rows printed `not on its place`. A CR sits above its dependencies; `stack` refuses otherwise. The final-order take (`final order`) may move any CR: rebase each moved one on the one under it, push, `ship`, `forge-stack rebuild` (or `create`), `forge-stack show`, the chain check, then `stack --out-of-draft`.
- Who moves a branch: a CR with no live Driver (ready or blocked) is rebased and pushed by you, by rebase, never a merge; a `working` CR's branch is its Driver's (the Foreman sends `note rebase: stacked on <cr below>`). Rebase and push each in the CR's own worktree (a missing one: `git -C <main checkout> worktree add <path> <branch>`), one `chantier push <cr> --lease <n> --unit stack` per branch (`help refused-push`), `ship` bottom up. A PR you move stays a draft.
- Check the chain: `git -C <its worktree> merge-base --is-ancestor <head of the CR below> <its head>` from the bottom, before you conclude a CR needs no restack and before any PR turns ready. Exit 0: based. Exit 1: restack. Any other exit: fetch and check again, never read it as "based". Matching PR bases prove nothing.
- Next: `help stack-record` (refusals, what a move touched, the notes).
