# The cut, the waits and the depends (part 1 of 2)

- The cut: when the user gave a time (a night, "by 9 o'clock") and the floor exceeds it, propose the largest set of CRs whose floor fits, short chains first; a CR enters only with every CR it waits for, and a chain may be cut after any of its CRs. The rest is "for later" (it stays where it is, `3-ready` or the backlog; nothing is moved before the go). Show the whole batch with its floor and the cut with its own; the user chooses, the go names the choice and `open` takes only the CRs chosen. No time given: no cut, the floor and its delivery time are said, nothing else. With the delivery time unknown no cut can be counted: say so in the plan.
- A parallel batch starts a CR as soon as a slot is free; every open PR is rebased after each merge. Touching the same file is no reason to wait: two CRs editing the same file do not depend on each other. Write `depends.json` in a CR's folder (`{"after": ["<slug>", ...]}`, a slug being the folder's name without its number) only when it needs another CR's result, merged or handed back ready first, and say in the plan what it needs; `open` and `order add` read it and exit 2 on an unknown slug, a malformed file or a cycle. A CR without the file depends on nothing.
