# Claude Code: the steering session's push in auto mode

The classifier blocks destructive git in subagents; the steering session's
`git -C <worktree> push --force-with-lease=...` goes through (not always) for the Chief of Staff in direct
mode. The Foreman is a session of its own, started with
the user's permission mode:

- **With the route rule set** an allow rule resolves a matching command before the classifier for
  a steering session (documented); **unproved** for the Foreman.
- **Without it** (P10 names it missing) the Foreman does not try: `push not tried: route rule
  missing`. Whether it would pass is **unproved**.
- **The user's yes**, in the Chief of Staff's conversation to a question naming the exact command,
  may let the classifier see the push is wanted: **unproved** unless the auto-mode docs say it.
- The first Chief of Staff turn gives once this alert: "Auto mode's classifier refuses some
  rebases and force pushes, with every rebase: a Driver's and the stack driver's restack. Without
  the rules, an unattended batch waits for you at the first one; with them a Driver's force push
  may still be refused. A refused one goes to the Foreman, then to me, who run a legitimate one on
  the Driver's own branch without asking you; you are asked only if the host refuses me too or a
  push is not legitimate; a push of a branch that is not chantier's is never run, you are told;
  in a remote session nobody may be there to answer."
