# Closing the batch (part 2 of 2)

- At a batch's end, at `close` and when the release waits, say it stays open while a CR is held (`close` refuses with it; the last ending command prints `the batch stays open`); name each parked or blocked CR with what it waits for and its way back as the CLI's line gives it, offer to wait or to send it out (`order drop <cr> --note trash|ready|P1..P4`), and act on the answer only.
- It refuses, naming each cause, while a CR is not merged or cancelled, an order is open, a stack agent is recorded, or a held agent (the current Foreman included) has a transcript showing it still runs or unreadable; also when nothing can be priced (no priced call, or no Foreman transcript recorded: no way through `close`). Other subagents and replaced Foremans never block: those listed apart need no question and no `--stopped` (their calls count in the final cost only up to now). An unpriced model does not refuse: the cost is a floor and the CLI names the id to add under `prices:`. Report a refusal with its cause; do not retry in a loop; do not `close --yes`. A held agent that still runs: wait for its hand-back, never a timer. `status`'s second line names the last closed batch. More: `help batch-close-stopped`.
