# The configuration and the team (part 2 of 3)

- A role is one of the plugin's agents (`cr-driver`, `stack-driver`, `qa-driver`, `release-driver`, `investigator`, `coder`, `inspector`, `debugger`, `verifier`, `conflict-resolver`, `demo-explorer`, `spec-writer`, `spec-critic`, `retro-critic`); it keeps its card, whoever runs it. `$CHANTIER playbook` prints what each role runs (the exact agent and model to pass; a configured `model` is a name the CLI resolves to the exact model, or refuses), or says there is no `chantier.yaml`. An invalid layer exits 2 with each problem and its line, and preflight's P12 fails: show the user the lines, never fix the file yourself.
- A role starts one of four ways: the plugin's agent (nothing set); the user's own agent (`agent`); the plugin's agent with a model (`model`), where the host starts a named agent with a model, else a generic agent with the role's contract in its prompt; the user's own agent with a model, which Copilot refuses: say so and offer to name the model in the agent's file. A role started generic runs with the caller's tools, not restricted: say it when you show the team.
