# A refused force push: run it, or climb

The route form, the one command of every steering-side push, from the main checkout, without changing its branch or touching its files: `git push --force-with-lease=<branch>:<expected> <remote> <local sha>:refs/heads/<branch>`, or `git -C <checkout> push …` when your directory is not that checkout (always with a planning surface: the project's clone that `take` names). One command per branch, never a loop or a script, even for a whole restack.
- Claude Code: run `$CHANTIER preflight` and read its P10 line starting `every batch:`. The route rule of the form you will run (`git -C * push --force-with-lease=chantier/* <remote> *chantier/*`, or the plain form) is missing when that line names it in an `(add …)` part, or a `denied:` entry (P10 cuts long commands) could be the form you will run. `<remote>`: the project's, `origin` unless configured. Only the P10 line counts. Missing: push nothing, `$CHANTIER note <cr> "push not tried: route rule missing"`, and send the `push` line below at once. Copilot skips this step.
Only that P10 line counts: the other preflight lines and the verdict are not yours to act on here.
Then `help refused-push-run`.
