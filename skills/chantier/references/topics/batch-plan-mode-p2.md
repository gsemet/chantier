# The mode question and the steering mode (part 2 of 3)

- The modes (`status`'s `batch:` line shows the shape): `parallel`, independent CRs, each on the default branch; `series`, one CR after the other, in the order given, each on the previous one's branch; `stack`, independent CRs that the stack driver then stacks. A word the user gave earlier answers the question. Always pass `open --mode` as the user answered; never take parallel by default (that is only the CLI's default for `open`). `order mode --note <mode>` switches on the user's word.
- Steering mode, direct (you steer, no Foreman) or Foreman. The argument counts only as the invocation's first word, exactly `foreman` or `direct`; anything else (`init`, a request) is the user's request and forces nothing (`direct Run the campaign …` is `direct` plus a request). Forced holds for every batch of the session until the user's word; that word ("you are in direct mode", "use a Foreman") works with or without an argument and also holds for the session.
- With no argument, the mode this surface can run, read at each plan, never frozen at the invocation: direct under the host's Remote Control notice (even if a Foreman could be reused) or on a host that cannot start a Foreman (a terminal, VS Code, a Copilot session whose session tools do not load: preflight P1 and P2), Foreman otherwise; no notice means local, so a missing one fails safe to Foreman.
