# Other re-take notes

- `unhold: <O-m>` (a held CR released while working): resume as a `resume:` does (`handoff <cr>`, the worktree as the stopped Driver left it); no round counted. In a stack, rebase onto the branch its `start` line names before the next `ship`.
- `rebase: <cr> dropped` (a held or parked CR this one waited with left the batch, series or parallel): rebase onto the base `take` or `handoff` names, leaving out the dropped CR's commits, retarget the PR to that base if elsewhere, push, `ship`, and go on; a conflict is a `conflict-resolver`. Taken back ready, it is the path of a `rebase:` note.
- `rebase: mode <mode>` (`order mode`; a stack dissolved first by `forge-stack unstack`): PR to draft first (`gh pr ready --undo`, `glab mr update --draft`), rebase onto the base `take` printed (parallel: the default branch or its open dependency's branch; series: its predecessor's, the bottom on the default branch), retarget, push, then `ship` (`--conflict` by `help conflicts`); a `ship` before the rebase is refused `branch not based on`. Read CI at the new head; long gate and `verifier` only when the carry does not hold. Hand back `ready`; the PR leaves draft once ready to merge (a series PR above the bottom stays draft).
- `folded: <k> merged into its branch` (GitLab only; unproved): `git -C <worktree> fetch`, `rebase origin/<branch>`, then `rebase <base>` (a conflict is a `conflict-resolver`'s; never `reset --hard`), push, `ship`; add one line naming the folded CR's change and its merged MR to `pr-body.md` (Deliverables, Internal references), post it, treat it as a move that changed the patch: `verifier` given the move, `inspector` (its `APPROVE` recorded first), long gate and CI at the new head, the description pass.
- `taken back: <why>` after your `handback ready`: the CR is yours again (`handoff <cr>`, then go on from `<why>`).
