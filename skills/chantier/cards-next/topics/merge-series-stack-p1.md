# A series batch, a stack batch, a mode switch (part 1 of 2)

- Series: CRs merge one by one in order. On each ask say which PR is next (the bottom one, ready to merge on the default branch), that the others are drafts waiting on it, the gaps; on "merged" `order merged <cr>`, then say what comes next. The user may merge the bottom PR as soon as it is ready to merge: nothing waits for a "go" of the user to merge. Never merge for the user.
- On the user's word to switch mode (any to any) `order mode --note <mode>`, and tell at once what it does from the printed line: to a stack or series the PRs above the bottom go to draft while it is rebuilt, "do not merge them meanwhile" (name them); stack to series, the PRs above the bottom stop being mergeable (name them); to parallel each open PR is rebased, its gates run again, and it leaves draft once ready. A merge the user makes anyway is recorded as any merge. Merged CRs never change.
- A series keeps the order given to `open` (`order add` puts a CR on top): the next CR starts once the previous one is `ready`, from its pushed branch, its PR a draft. A CR with a dependency starts only once it is `ready` (`take` refuses until then), on the branch of its last dependency still open, else on the default branch; its PR stays a draft until the dependency merges.
