# After the release PR merged

A merged release PR (you see it on the forge, and `release go` answers `go` because of the merge) needs no further go from chantier.
- A step after the merge waits for the user's word when the procedure, the release CR's specification or the take note holds it for approval. The approvals are in `handoff`'s `approvals unused:` line, the `approved:` notes and the take note (under a grant too; the merge under the grant spends none). A `wait: <step>: …` note later than the approval of the same step is stronger: that step is held as if never approved.
- Run the procedure's steps in its order, approved ones included. At the first held step with no approval: `handback blocked approval: <that step>[; <each later held step with no approval>]`, the steps already run named in a `note`. A later held step already approved is not asked again.
- The main-checkout step (for chantier, `CONTRIBUTING.md` "Release" step 4, `just tag`) is never yours, in the main checkout or your worktree. When the procedure reaches it, the approval rule applies first; once approved, name the steps already run in a `note`, then `handback blocked waits: the steering session runs <the step> in the main checkout`. A take note starting `tag done:` says it ran: go on from the next step, never run it again. Check its result read-only (for chantier, `git -C <worktree> ls-remote --tags origin v<X.Y.Z>`); the tag missing: `handback blocked question:` naming it.
- A step that waits for a long pipeline on the default branch is a typed wait: `handback <cr> blocked <reason> --wait pipeline=<sha> --lease <n>`, or, when you go on with other steps, `wait <cr> add pipeline --ref <sha> --link <PR link> --note "<text>"`. Never poll it.
- Publication (for chantier, "Release" step 5, `gh release create … --verify-tag --notes-file …`) is yours once `release go` answers `go`, when the host lets it through. A host refusal is reported with its exact text as `handback blocked approval: publish: <the exact command>`; try nothing else. The command must run as written after you end: the notes file and assets are in the CR's work folder or the worktree, never a temporary folder you clean up. Name the steps already run in a `note` first.
- Publication done by someone else (a take note or message starting `publication done:`): not a new attempt, no `release start`, no step run again, never the publication command. Check read-only: `gh release view <tag> --json url,tagName,isDraft`, `glab release view <tag>` (unproved). Found and not a draft: done (its text may differ from the notes); run the later steps that are yours, then `help release-end`, whose `release published` takes the forge's link. Not found, or a draft: `handback blocked approval: publish: <the exact command>; not on the forge: <first line printed>`, nothing else.
