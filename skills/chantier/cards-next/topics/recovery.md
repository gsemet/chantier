# Recovery

A stale heartbeat says something only while a CR is `working`; with none the Foreman has stopped waking, as it should. "Heartbeat stopped" is a loop ended on purpose. After a break, restart or stale heartbeat, prove the Foreman is alive (`$CHANTIER foreman get`; the host knows the session and it answers a `ping`) before reporting progress.
- An app restart stops every session: tell the user, and on "resume" run preflight again and start a new Foreman with the next number (or on the user's word switch to direct mode, `help mode-switch`), adding "Resume: relaunch each CR still working by the restart path (`agents set <cr> - --epoch <n>`, `handoff`, `take <cr> --note "resume: <cause>" --epoch <n>`, a new Driver, `agents set <cr> <id> --epoch <n>`); a relaunched CR's stale long gate is stopped by its new Driver with `$CHANTIER gate <cr> --stop`."
- `cancel` follows only a drop the user ordered (`order drop <cr> --note ...`): never use it to stop the processes of a CR that goes on.
- A Driver whose id was cleared (`agents set <cr> -`) and a replaced Foreman never block `close` (their transcripts are listed apart and need no `--stopped`), nor do the session's other subagents; the CLI judges a transcript by its end, never the file's age. In a direct batch a Driver stopped from outside is restarted by you with no question (`help lost-driver`), and when you stop a Driver and do not restart it at once you clear its id in the same turn.
