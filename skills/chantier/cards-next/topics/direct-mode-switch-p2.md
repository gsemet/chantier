# A switch to direct mode (part 2 of 4)

4. A live Foreman: send `[chief-of-staff→foreman] switch to direct mode` and start nothing until its `switched to direct mode <batch>: stopped <what>` line comes. One that answered the ping but sends no such line: keep waiting; only the user's word moves it to "not answering". This path works under Remote Control too.
5. A Foreman not answering: its session is stopped by the user, or by you on the user's yes where the host row names the means (Claude Desktop `mcp__ccd_session_mgmt__stop_session`; Copilot: none recorded, the user stops it). Under Remote Control say the stop needs the machine (stopping a session from the phone is unproved). In every case name the session to the user (its title and the id `foreman get` prints) and wait until it is stopped.
6. Has each old Driver ended? Before any restart, `$CHANTIER close --batch <batch>` (the check, never `--yes`) lists each held agent's transcript state. Restart only the CRs (and the stack driver, QA orders) whose old Driver is shown ended; for one shown running or unreadable, ask the user, and restart it only once the user says it is stopped. Never assume that stopping a session ended its Agent children. On the live-Foreman path the `switched` line names what stopped; the same check confirms it.
