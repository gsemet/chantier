# A CR taken back

Work on a CR handed back `ready` or `blocked` (a rebase, fix, answer, red check, merged dependency) reaches a Driver only through `take <cr> --note "<why>"`. Just before a work note, read a plain `$CHANTIER status` (no `--refresh`, no `--epoch`), never your last wake's state: `ready` or `blocked`, `take`; `working`, `[foreman→driver <cr>] note <text>`. A hand-back crossing it returns from the Driver: take it back then. `take` reopens it `working`, no round; its Driver ships, passes the gate and `VERIFIED` before `handback ready`.
- From `ready`: note the Driver's agent id (`status`), `agents set <cr> - --epoch <n>`, `take <cr> --note … --epoch <n>` (a slot, or it waits), send that Driver `[foreman→driver <cr>] note taken back: <the note>`, `agents set <cr> <id> --epoch <n>`. No id, a refused send, or no answer by the next wake: `agents set <cr> - --epoch <n>`, `take <cr> --note "resume: <the note>"` (working: no new slot), a new Driver.
- From `blocked`: a new CR Driver. One whose Driver is still recorded may hand back `ready` itself (`hand-back ready … it was blocked: …`): no `take`, handle it as ready (a release stays `blocked` until `take`).
- `blocked` with `; waits: w1 approval`: on the user's answer or a `wait-cleared@1` line, `wait <cr> clear <id> --epoch <n>`, then take it back. A `blocked waits: <what>` is no ask: take it back when that lands.
- A gap the body lacks: `take <cr> --note "gaps: <what is missing from Known gaps>"`, no ask.
