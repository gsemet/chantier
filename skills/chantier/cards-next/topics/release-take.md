# A release CR in the batch

The Release driver takes the release CR once the others are handed back ready (ordered batch; in a stack, `take stack` first, then `take <release>`) or merged (parallel batch) (nothing to confirm). It waits while a CR is held or parked (`help hold`).
- On the merge of the release PR (`order merged`), start the Release driver again at once. The take note names the steps the user approved before the merge, from the `approvals unused:` line of `$CHANTIER handoff <release-cr>`: `take <release-cr> --note "merged: <pr>; approved before the merge: <step>; <step>; the other irreversible steps wait for the user's word"`. With no approval, the note says the steps wait for the user's word. A step with a `wait: <step>: ...` note later than its approval is named held: `... approved before the merge: <step>; held (wait): <step>; ...`. Your own `release go <cr> --note "merge <pr>"` spends no approval, so the list is the same whoever merged.
- An `order approve` on a release CR handed back `ready` whose PR waits for its merge is no work for a Driver: `order done` at once, no `take`. On one `blocked approval:`, the take carries the note.
- An `order note` starting `publication done:` on a release CR `blocked approval: publish: ...`: `take <release-cr> --note "<the order's note>"` at once (`agents set <cr> -` first when the id is recorded; `order done` once taken); it is no new attempt. While its Driver is still `working`: `[foreman→driver <cr>] note <text>`.
