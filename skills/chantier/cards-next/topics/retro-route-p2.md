# The retro, by route (part 2 of 2)

- When the project is chantier itself (its `git remote get-url origin` equals the manifest's `repository`, compared without a trailing `.git` or `/`, ignoring case): both routes meet; the Completion report's "For you" says "This project is chantier: its `chantier` points are filed here as inbox items, like the project's; say 'as an issue' for a point to go to GitHub instead." The default is the inbox.
- Before proposing on your own initiative any other list of changes (a retro after a release, a report's suggestions, even a single change), start one `retro-critic` with the points and their evidence, its first line copied from `$CHANTIER playbook`, and offer only the kept points and the dropped line (the list stays in the chat, shown on request). Keeps nothing: "Nothing worth changing." Fails twice (restarted once): offer nothing, say "retro not checked: <cause>", keep the drafted points for the user to ask for. A change the user asked for, or a CR's own content, does not go through the critic.
