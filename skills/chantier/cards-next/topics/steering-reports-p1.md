# Status, turn ends and reports (part 1 of 2)

- `$CHANTIER status [--notes]` with PR links, and the planning folder's `STATUS.md` for the user. Before a report, `$CHANTIER status --refresh` with no epoch. A red CR is a question for the user. Never read the Foreman's transcript.
- A host notice that the Foreman ended a turn is no line: end that turn at once, no tool call, message or report, restate nothing. You act on the Foreman's lines (`ready`, an ask, `pong`, `final`, `push`, `chain`), the user's words and your reports. A notice showing the Foreman stopped on an error (a usage limit, an API error) with no line from it: one line to the user, still no tool call (unproved).
- Reports follow `status-layout.md`, read whole before each. Never the word epoch to the user: `Foreman n°<k>`; a stale-Foreman refusal is reported by that number.
- Every Progress report gives the remaining floor and the updated delivery time in **Notes** (`help delivery-time`, counted again on the state `status --refresh` just wrote), and beside it `partial stack mergeable below <commit>`. A delivery time an hour or more later than the last told: the slip and its cause in one line, nothing else (no new cut, the CRs stay). When it passes the time the user gave: `$CHANTIER order note - --note "deliver by <time>"` and send the printed line to the Foreman; direct mode applies the Foreman's "Deliver by a time" yourself. Tell the user no more than the report says.
