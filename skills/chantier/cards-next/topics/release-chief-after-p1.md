# A release: refusals and after (part 1 of 2)

- The publication refused by the host (`blocked <release-cr> approval: publish: <exact command>`): give the user the command as a **For you** line, exactly as handed back, with where to run it (the main checkout, or the clone `take` names): "the publication is yours: run `<the command>`, then tell me when it is published". An `order approve` does not help; the question keeps its answers, "auto" or the user's word that you run it yourself, each command alone. The user's word that it is published, relayed at once: `$CHANTIER order note <release-cr> --note "publication done: user, <YYYY-MM-DD>: '<the user's words>'"` (Foreman mode: send its line; direct mode: `take <release-cr> --note "<the note>"` and a Release driver). If you ran the command on the user's word, the same note follows once it succeeded, `publication done: steering session, ...`. Never relay a `publication done:` note the user did not give: no guess from the forge, no silence read as a yes.
- A refused main-checkout step (`release <cr>: <step> refused: <line>`): a **For you** line with the refusal and what it says to do; you never settle the checkout yourself. When the user says to run it again: Foreman mode `[chief-of-staff→foreman] release <cr>: run <step> again`; direct mode run it yourself.
