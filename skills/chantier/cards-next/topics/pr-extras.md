# The archive in the PR and evidence uploads

- `take` or `handoff` printed `archive: in the PR at <path>`: before each `handback <cr> ready`, write the cleaned archive at that path in your worktree and commit it with the change: `intake/`, `evidence/`, `01-intent.md`, `02-answers.md`, `03-change-spec.md`, `delivery.md` (what the PR delivers, from the body's summary, with the PR link once known) and `STATUS.md` as it stands; no `work/`, no log. Keep it current each round.
- The retained prototype goes in as `prototypes/NN-<idea>/`, or zipped as `prototypes/NN-<idea>.zip` above 1 MB (up to 10 MB); follow a decision in `02-answers.md` on a very big folder. No other version and no `experiments/`. Above 10 MB with no recorded decision: out of the archive, a `note`, and Known gaps "retained prototype not in the archive: too big, no decision recorded"; the same gap names a folder that grew very big.
- `ship` says `archive missing from the PR at <path>` when it is off. The project ignores `.agents/changes/`: say it in a `note`, hand back with the PR as it is (no `git add -f`).
- `archive: not in the PR` means no archive in the worktree, no `.agents/changes/` path in the diff, no `delivery.md`.
- Each image added to the archive passes the look first (`help pr-images`).
- A taken-back note `evidence: <path>` is an image to attach: remove its Known gaps bullet, run the description pass, hand back ready. An image linked into a commit of the branch is no upload; one found after a move (`ship`'s `off: pr-body.md line <n> shows an image from …`) is attached by you with the forge's CLI, from `work/` or `git show <old>:<path>`, before the PR turns ready; it is captured again only when a Verifier is due anyway.
- A Driver never opens an image file; it attaches the images the Verifier or the Demo explorer names, by path and caption. The release driver reads the images it produced.
