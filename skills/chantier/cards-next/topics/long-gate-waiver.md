# A hand-back that says its long gate is waived

- `long gate waived (O-<k>)` is checked against the recorded order (`status` lists it; `order waive`), not the rules: it holds when the order is there and its scope fits (`validated by CR-<top>'s gate`, or `follow-up <folder>`). The ask then carries `long gate waived: validated by CR-<top>` or `long gate waived: follow-up <folder>`. No such order: `take <cr> --note "long gate: no waiver recorded for this CR"`, no ask. A brief carries of a waiver only what `take` prints (`gate:`).
- A waiver waives the local run only when its words name that gate (`status`'s `O-<k> waive <cr> <note>`, or the CR's `STATUS.json` `gate.waiver`): the CR then owes no local run and its ask carries no clause. Else `help local-gate`.
- A waiver is the user's word, recorded by the Chief of Staff: `order waive stack --note "<words>"` (a stack: one long gate on the top PR only; every open CR but the top, one added later too, is waived; the top never is, its gate or a carried pass validates the others and moves up when a CR joins) or `order waive <cr> --note "<words>" --follow-up <backlog folder>` (nothing in the batch validates it: the follow-up CR runs the gate on main, and exists first). `handback ready` then skips only the gate pass (head, clean, pushed and `VERIFIED` checks stay).
