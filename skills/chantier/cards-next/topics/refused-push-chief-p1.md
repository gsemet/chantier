# A refused force push, your part (part 1 of 2)

On `[foreman→chief-of-staff] push <branch> <expected remote sha> <local sha>` (direct mode: the Driver's `push` line) the push climbs to you. A covered branch (any `chantier/*` branch that is not the default branch, `--force-with-lease`) is never a question for the user: judge it and run it. The check and judgement are the Foreman's (`help refused-push`), run again in full whatever its note says, at the shas of the line; read `handoff <cr>` for its `push judged legitimate` and `refused:` or `push not tried: route rule missing` notes. In direct mode the gate check and its skips are yours, once.
- Legitimate: `$CHANTIER note <cr> "push judged legitimate at <local sha7> for <branch>: <one line>"`, then the plain `git push --force-with-lease` in the route form, no ask. Accepted: answer `pushed <branch>` (direct mode: the CR's `take` note); the user hears nothing.
- A hard check that fails (a branch `handoff` ties to no CR of this batch, or no long gate passed at the local head outside the skips): push nothing; `$CHANTIER note <cr> "push refused <branch>: <reason>"`; answer `push refused <branch>: <reason>`; no user question.
- A Driver's refused push of a branch that is not a `chantier/*` branch, or of the default branch: push nothing, ever; record and answer `push refused <branch>: not a chantier branch`; tell the user as information (branch and CR); a yes does not push it. Your own push of one: the card's ask-first item 5.
