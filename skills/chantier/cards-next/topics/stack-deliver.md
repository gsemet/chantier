# Deliver by a time, in a stack

On the order note `deliver by <time>`, until the time, free slots go first to the CRs that can join the mergeable part by then: those closest to `ready` whose dependencies are already in it or ready to merge, short chains before long ones; a CR that cannot be ready by then is not started over one that can. You judge which, from each CR's state and chain. No started CR is stopped. Name the time in the stack driver's take (`take stack --note "deliver by <time>"`).
At the time, the stack on the forge is what the user gets: if it is not complete and no ask was sent for it, send the `stack-ready-to-merge … to come: …` ask of the stack as it stands, with the local-gate clause as the hand-back gives it (`not run` or `failed` included: the time overrides the condition of `help stack-run`). Then the batch goes on toward the complete stack. In a parallel or series batch, the same note sends each owing CR's ask as it stands (`help local-gate`).
