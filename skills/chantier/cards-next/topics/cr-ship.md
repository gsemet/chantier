# Commit, push, PR and proof

- All approved: check nothing changed since the review (`git -C <worktree> status --porcelain`, `diff --stat` show the reviewed files with the same contents; a file touched after the review means a new `inspector` before the commit). Commit by name (`git -C <worktree> add -- <paths>`, never `-A` or `.`); check `diff --stat <commit> -- <paths>` against the reviewed state is empty and the tree clean; `note <cr> "r<n> approved at <head from the JSON>, committed as <sha>"`.
- Commits: a PR merges by rebase with every commit, so each commit, a checkpoint included, has a message in the project's commit style (else a Conventional Commit subject) saying what it holds. Never `wip`, "pending", "checkpoint", a round or review state, a CR number, a batch or a role. A commit a procedure names keeps its message. Folding: `help checkpoints`.
- Then the matrix probe (`help matrix`), `rebase` (fetch, `rebase <base>`; a conflict is a `conflict-resolver`; never stop a process by name, `kill` yours by id; a command the host may refuse runs alone), the checks before the first push, the long gate (a failure is a round), push, the PR, `ship`, CI, then a `verifier`.
- Before the first push, run the project's fast gate and any pre-push check its rules name (`$CHANTIER rules`) in the worktree at the rebased committed head, yourself, one command per call, never through `gate`; one note per command: `before first push at <sha7>: <command>: pass`. A failure is a round. No fast gate and no pre-push check: nothing to run, no note.
- Push with `chantier push <cr> --lease <n>` (`help refused-push`). Open the PR yourself as a draft (`gh pr create --draft --body-file <work folder>/pr-body.md`, `glab mr create --draft`; GitLab: `help pr-gitlab`), title and `pr-body.md` from the project's PR template, else the shipped one, the `## Issues References` section for `issue:` lines only. Before each post, read `pr-body.md` once against the template's audit list (internal references and Known gaps first) and fix it; it replaces neither the Inspector's audit nor the Verifier's pass. The PR's base is the `base` `take` printed, never another.
- `$CHANTIER ship <cr> <pr link>` reads the base and draft state, records the PR at this head, and says what is off. A change of base or draft state on the forge is followed by `ship`.
- Next: `help cr-proof` (the verifier, the gaps, the evidence).
