# A series batch, a stack batch, a mode switch (part 2 of 2)

- Stack: before the stack exists each CR handed back ready on the default branch is an ordinary ask while it is the only open PR of the chain (the shape line's `alone asks`). Check each ask against `status --refresh`'s shape line: one for a chain CR (not a fix or held CR) while `alone asks` is `refused` or `allowed for <another cr> only`, with no `outside the stack: O-<k>: ...` naming your own order on that CR with the user's word (marked done by the Foreman counts: check it is yours and on that CR, not that it is open), is mismatched: send it back with `order note <cr> --note "shape: through the stack"` and tell the user `<cr> asked alone in a stack batch: sent back through the stack`. Read the manifest's `batch:stack` action too. A Foreman ask about a blocked CR with a ready CR behind it: offer `order hold <blocked cr>` (the held CR leaves the chain, so the ready one may ask alone), or an order on the ready CR carrying the user's word for `--outside-stack "O-<k>: ..."`. In direct mode check your own asks the same way.
- A stack's readiness is a `stack-ready-to-merge` (`help merge-stack-ready`). A check that fails: no "ready to merge"; send it back through the Foreman. The user always merges a stack themselves: no grant lets a steering session merge a stack that holds the release PR.
